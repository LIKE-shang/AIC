## 已实现

`competition_rehearsal.py` 是纯 Python 状态机，无 ROS、串口、动态库或飞控连接：

1. 等待模拟悬停到达与初始关光回执。
2. 接收对应编号靶的有效观察，等待居中、稳定的连续新帧。
3. 输出模拟开光意图，等待本次请求的匹配回执。
4. 根据模拟光斑反馈连续计时；回执本身不算命中。
5. 输出模拟关光意图，确认本次关光后才计完成或进入下一靶。
6. 移动只输出靶位编号，不生成位置、速度或姿态控制量。到达后重新获取视觉证据。
7. 全部完成后等待模拟 POSCTL 状态读回，由操作者降落。

支持单靶、明确的无重复靶序列、1–3 中随机选择两个不同靶位。随机结果在开始时冻结，可用 seed 重放。三个相同三环图案自身不能判定靶号，真实系统仍需要定位建立靶号对应关系。

重复帧不增加连续观察时间；丢靶、光点丢失、状态过期、定位失效、接管等进入终止状态，并输出模拟关光意图，不重新接管。ABORT 的模拟关光请求不表示物理激光已关闭。

## 运行离线演练

在源码目录执行（仅 Python 标准库）：

```bash
python3 autonomous_window_test/tools/rehearse_competition.py --targets 1
python3 autonomous_window_test/tools/rehearse_competition.py --targets 1 2
python3 autonomous_window_test/tools/rehearse_competition.py --targets 1 3
python3 autonomous_window_test/tools/rehearse_competition.py --random-two --seed 7
python3 -m unittest discover -s autonomous_window_test/test -p 'test_competition*.py' -v
```

`--output` 可保存 JSON 结果，只允许新文件，避免覆盖已有记录。所有结果显式包含 `hardware_commands_sent=false` 和 `physical_hit_verified=false`。脚本没有 `--execute` 选项。

## 现有起飞代码复用验证

`test_competition_flight_rehearsal.py` 使用既有 `Mission` 和合成飞行反馈，测试位置目标起飞至 0.9 m、单靶模拟流程、关光意图、POSCTL 交接与接管不重入。仅测试中衔接，生产 `mission.py`、`auto_window.py`、原地面激光桥均未修改。

它不是实飞入口，不代表已经完成 ROS 集成、飞控部署或物理命中验收。跨靶 MOVE 目前仍是编号意图，未做轨迹或碰撞检查；不要将其直接映射成实际位移。
